27-09-2026 — false-positive reduction
- BOLA (API1): sensitive data (e-mail/token) telt alleen nog als BOLA-hit bij
  daadwerkelijk gedetecteerde cross-user-toegang; een 200 met de eigen gegevens
  is geen kwetsbaarheid meer (bola_audit.py).
- BOLA: het "ander object-ID in de response"-heuristiek geldt alleen nog voor GET;
  bij PUT/POST/DELETE betekent een nieuw ID dat de server een resource aanmaakte.
- BOLA: _filter_issues houdt alleen nog bevindingen met cross-user-bewijs; de regel
  die elke Medium/High/Critical-severity hield is verwijderd.
- Chain Mode: rapporteert alleen nog geslaagde (2xx) Medium/High-escalaties in
  plaats van alle requests; HTTP 0/4xx/5xx "Low"-ruis wordt niet meer gerapporteerd.
- Chain Mode: auth/actie-endpoints (login, signup, forget-password, reset-password,
  verify, ...) worden overgeslagen als escalatiedoel (altijd 200 -> false positives).
- Broken Auth (API2): secret-exposure en password-hash checks slaan HTML-pagina's
  over; een catch-all/loginpagina (200 + text/html) wordt niet meer als uitgelekt
  secretbestand gemarkeerd.
- Misconfiguration (API8): schema/spec-exposure vereist nu echte JSON/YAML-content
  in plaats van alleen de bestandsextensie; HTML-pagina's worden overgeslagen.
- Swagger generator: ontbrekende `import os` toegevoegd (crash-fix bij crawl).

- Beter error handeling, but still need some extra work to do, working on a new version that use a sqlite database for all scan results, is now in Beta
- Using openapi_universal.py. A version-agnostic OpenAPI helper that loads specs (JSON/YAML), iterates operations, builds concrete HTTP requests (params/bodies), and applies security config. Because Swagger 2.0 and OpenAPI 3+ differ in structure, a universal loader lets the scanner treat every spec the same no per-version parsing or special    
  cases. That consistency reduces maintenance and bugs, builds accurate requests from schemas/auth automatically, improves coverage, and cuts false positives.
